**進度**：正在調整`config/runtime.yaml`裡的`end_of_speech_silence_chunks`等參數，調完會用真實語音跑`progress/p4_kpi_measurement/run_voice_latency_test.py`重新量測，把真實數字（不是理論估計）回報給你。**誠實預告**：純ASR轉錄本身大約要1.5秒，物理上很難讓整體壓到1秒，但會把不必要的安全邊際盡量壓縮，把真實能做到的數字老實報給你，而不是假裝能達到1秒。

### 4.2 喚醒詞8小時誤觸發率測試 ✅ 你已決定：取消，改用更根本的解法

**你的決定**：取消這個測試，改成「主介面加一個喚醒詞開關，預設關閉，關閉時電腦不能在你不知情的狀況下自己做任何小事」。

**已完成**：`companion.html`最上面新增一個「啟用喚醒詞」勾選框，**預設關閉**。關閉時，喚醒詞偵測模型本身根本不會被拿去跑預測（不是「跑了但忽略結果」），從程式邏輯上保證不可能觸發任何動作——這比原本規劃的「測量誤觸發機率多低」更根本：不管誤觸發率是多少，只要開關沒打勾，誤觸發都不可能造成任何實際操作。已寫成安全測試`src/test_wake_toggle_safety.py`，用真實的喚醒詞音檔驗證過：開關關閉時，講喚醒詞完全沒有觸發任何事件；開關打開時，功能一切正常運作。這個設計取代了原本的8小時測試需求，這個KPI項目視為已用另一種方式解決，不再需要無人值守測試。

### 4.3 （低優先度，僅供參考）Xbox Game Bar螢幕錄影功能

**現況**：`record_screen`工具的程式碼邏輯是對的，但這台機器的Xbox Game Bar背景服務起不來，沒辦法真的驗證錄影檔案會產生。這不影響其他任何功能，優先度低，**不需要你現在處理**，除非你之後真的想用語音錄螢幕，到時候我們再一起排查（可能需要你手動先在Windows設定裡確認Game Bar有正常啟用過一次）。
